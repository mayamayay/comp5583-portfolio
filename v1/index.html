证券交易综合运营平台 · 数据归档模块

毕业设计 · 2026 · 独立完成

问题

证券交易系统每天沉淀大量订单与成交记录，长期留存既是合规要求，也拖慢在线库的查询。手工归档不可追溯，出问题无法证明数据完整。

做法

设计"策略—任务—元数据"三层结构：策略定义归档范围与周期，任务负责调度与执行，元数据记录每一批数据的去向。归档后提供检索、恢复与完整性校验三条通路。

结果

系统覆盖策略配置、任务管理、元数据浏览、数据检索、数据恢复、完整性校验与合规报表导出七个功能域，并按管理员与普通用户两个角色隔离权限。

7功能域
2角色权限层
4核心归档表

我的贡献：需求梳理、数据库设计（archive_policy / archive_metadata / archive_task / archive_restore）、后端归档执行逻辑、前端页面与权限菜单。

展开技术细节

后端基于 Spring Boot 3.x（Jakarta EE 命名空间），前端为 Vue 3 单页应用，权限与菜单沿用 RuoYi 的 RBAC 模型。归档执行采用定时任务触发，单次执行按策略批量迁移并写入元数据快照。
