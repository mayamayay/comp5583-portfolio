项目

证券交易综合运营平台 · 数据归档模块

毕业设计 · 2026 · 独立完成

  • Spring Boot 3.x
  • Jakarta EE
  • Vue 3
  • RuoYi 框架
  • MySQL
  • RBAC

这是一个面向证券交易场景的数据归档系统。交易系统每天沉淀大量订单与成交记录，长期留存既是合规要求，也会拖慢在线库的查询；手工归档不可追溯，出问题时无法证明数据完整性。系统目标是把历史数据按策略定期归档，同时保留检索、恢复与完整性校验三条通路。

  • 核心表 4 张：archive_policy、archive_metadata、archive_task、archive_restore
  • 权限分 2 层：admin（menu_id ≥ 2000）与 common（1–1060）
  • 功能域 7 个：策略、任务、元数据、检索、恢复、校验、报表
  • 归档模型：策略 → 任务 → 元数据快照，逐批可追溯

我负责归档模块的整体设计与实现。数据库层设计上述四张核心表，用策略表描述归档范围与周期、任务表承载调度与执行状态、元数据表记录每一批数据的去向、恢复表保存回灌请求。后端基于 Spring Boot 3.x 与 Jakarta EE 命名空间实现归档执行逻辑，前端为 Vue 3 单页应用，权限与菜单沿用 RuoYi 的 RBAC 模型，按管理员与普通用户两个角色隔离可见范围。归档执行由定时任务触发，单次执行按策略批量迁移并写入元数据快照，完整性校验环节对归档前后记录数与校验和做比对，结果可导出为合规报表。

金融文档本地检索工具 （拟议项目）

个人项目 · 规划中

  • Python 3.13
  • PyMuPDF
  • 倒排索引
  • 本地优先

金融文档的 PDF（年报、招股书、募集说明书）分散在多个目录，系统搜索只能命中文件名，找不到正文内容。这个项目要做一个本地运行的全文检索工具，全程离线、不上传任何文件。

  • 解析层：PyMuPDF 抽取 PDF 正文，原生解析 Markdown，按段落分块
  • 索引层：词项到文档的倒排映射，先落盘为简单段式结构
  • 查询层：支持短语查询与布尔组合
  • 状态：已完成技术选型与索引结构设计，尚未编码

这是我为练习检索系统基本原理而提出的项目，目前处于设计阶段，不是已交付的成果。设计上优先保证正确性，压缩与增量更新留到功能跑通之后再考虑。
